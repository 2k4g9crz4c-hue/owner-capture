# 外部脳インストーラ（owner-capture版） v1.0

owner-capture（`index.html`）で保存したMarkdownファイル
（frontmatter: `title` / `created` / `category` / `tags`、カテゴリは
`Inbox` / `Decision` / `Idea`）を迎え入れるための、Obsidian用「外部脳」
Vaultを本人と一緒に作る手順書。

このファイルの2階層上（リポジトリのルート）に `README.md` と
`index.html` がある。owner-captureはブラウザだけで動くMarkdown生成
ツールで、生成したファイルを手動でVaultに置く運用が前提。このスキルは
その受け皿となるVault側を整える。

コードは実行しない。ソフトの導入・定期実行・同期設定・公開もしない。
Markdownファイルとフォルダ構成を本人用に組み立てるだけ。

## 守ること（優先順）

1. 日本語で、一度に1問だけ聞き、回答を待つ。指定済みのことは聞き直さない。
2. 既存Vault（モードB）では、承認なしに既存ファイルの内容を変更・削除
   しない。必ず「これを追加/変更してよいか」を提示してから実行する。
3. owner-captureのfrontmatter形式（`title`/`created`/`category`/`tags`）
   と初期カテゴリ（Inbox/Decision/Idea）との互換性を壊さない。拡張する
   場合も同じキー構成を踏襲する。
4. コード実行・自動化・定期実行・外部への送信は一切行わない。作るのは
   フォルダとMarkdownファイルのみ。
5. 迷う場面では決め打ちせず、選択肢を提示して選んでもらう。
6. 作業が中断しても、次回どこまで終わっているか本人が見て分かる状態
   （作成済みフォルダ・README等）を保ち、同じ質問を繰り返さない。

## 全体の流れ

### ステップ0: モード選択（最初の1問）

「外部脳を新しく作りますか？　それとも今あるObsidian Vaultを整理し
ますか？」

- A. 新規構築
- B. 既存Vaultの診断・整理

回答に応じて以下のモードA/Bに進む。

---

### モードA: 新規構築

1. **設置場所を聞く**
   「このリポジトリのフォルダをそのままVaultにしますか？　それとも
   別の空フォルダに新しく作りますか？」
   - 別フォルダの場合はパスを聞く。

2. **カテゴリ構成を聞く**
   「保存先のカテゴリは、owner-captureの初期カテゴリ（Inbox /
   Decision / Idea）のままでよいですか？　追加したいカテゴリはあり
   ますか？」
   - デフォルト: Inbox（未整理の受け皿）/ Decision（決めたこと）/
     Idea（アイデア）
   - 追加があれば、フォルダ名とfrontmatterの`category`値をセットで
     確認する。

3. **フォルダ名の対応を確認する**
   デフォルト案を提示し、Yes/Noで確認する：
   - `Inbox` → `00_Inbox/`
   - `Decision` → `10_Decision/`
   - `Idea` → `20_Idea/`
   - 追加カテゴリは番号を繰り下げて連番にする。

4. **補助的な仕組みが欲しいか聞く（任意・1問ずつ）**
   - 索引ノート（`README_はじめに.md`）は作る前提。内容に入れたい
     項目（運用ルールなど）があるか聞く。
   - Dailyノート用フォルダが欲しいか聞く（不要なら作らない）。

5. **作成する**
   確認が済んだ項目のみ、以下を作成する。
   - カテゴリごとのフォルダ（空でも可。中身の説明は
     `README_はじめに.md`にまとめる）
   - `README_はじめに.md`（`templates/README_はじめに.md`をベースに、
     実際のフォルダ名・カテゴリ対応表を反映）
   - カテゴリごとのテンプレートノート（`templates/*.md`をベースに、
     フォルダ内または`_templates/`フォルダにコピー）

6. **完了報告**
   作成したフォルダ・ファイルの一覧と、次に owner-capture で保存した
   ファイルをどこに置けばよいかを1つの表にまとめて提示する。

---

### モードB: 既存Vault診断・整理

1. **Vaultのパスを聞く**
   「整理したいObsidian Vaultのフォルダパスを教えてください。」

2. **現状を調べる（読み取りのみ）**
   - フォルダ構成
   - 既存ノートで使われているfrontmatterのキー（`title`/`created`/
     `tags`など）
   - カテゴリらしき運用（フォルダ分けやタグ）の有無

3. **診断レポートを提示する**
   owner-captureのMarkdownを迎え入れる観点で、足りないもの・ズレて
   いるものを一覧にする。例：
   - `category`に対応するフォルダ/仕組みが無い
   - `tags`の書式が配列でない
   - Inbox相当（未整理の受け皿）フォルダが無い

4. **改善案を1つずつ確認する**
   一括提案はしてよいが、実行は必ず項目ごとの個別承認を得てから行う。
   「Aを直しますか？（はい/いいえ/保留）」のように聞く。

5. **承認された項目だけ反映する**
   - 既存ノートの本文は書き換えない。
   - 反映は「新しいフォルダ/テンプレートの追加」「README_はじめに.md
     の新規作成」など非破壊的な方法に限る。
   - 既存frontmatterを直す必要がある場合も、対象ファイルと変更内容を
     具体的に提示し、承認を得てから1件ずつ行う。

6. **完了報告**
   変更した内容・見送った項目（保留分）を一覧で提示する。中断した
   場合、次回この一覧から再開できるようにしておく。

---

## テンプレート

- `templates/README_はじめに.md` — Vault用の索引ノート。フォルダ構成と
  owner-captureとの連携方法を説明する。
- `templates/Inbox.md` — 未整理メモ用テンプレート。
- `templates/Decision.md` — 意思決定の記録用テンプレート。
- `templates/Idea.md` — アイデアメモ用テンプレート。

いずれもowner-captureのfrontmatter形式
（`title`/`created`/`category`/`tags`）に合わせてある。新しいカテゴリを
追加する場合も、同じキー構成を踏襲したテンプレートを作ること。
